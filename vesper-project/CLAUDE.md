# SysaiQ — bilingual living-interface landing page

Brand casing is **SysaiQ** (matches the hexagon logo). Uppercase contexts
(eyebrows, HUD) use SYSAIQ. Logo source: `assets/logo-src.png`; derived
assets (`logo-mark-160.png` keyed-transparent header mark, `favicon-64.png`,
`about-art.jpg`, root `og.jpg` 1200×630) are canvas crops of it — regenerate
from logo-src.png if the logo ever changes. `{{LOGO_MARK_URI}}` and
`{{FAVICON_URI}}` are inlined by build.py in the baked pages and become
`/assets/…` URLs in the runtime templates (`about-art.jpg` is no longer
referenced by the template); og.jpg stays a real file (crawlers need a URL).
`CNAME` is a leftover from GitHub Pages; the site is served by the Ubuntu
box (see `../DEPLOY.md`).

The SysAIQ.com landing: a single-page WebGL experience where one
91,000-particle field morphs through four states as the visitor scrolls:
breathing orb → ring galaxy → Earth (real coastlines) → "SysAIQ"
letterforms. Fully bilingual (Persian RTL / English LTR) from one shared
template. Everything is deterministic (seeded mulberry32, SEED=20260808).

## Files

- `src/vesper.src.html` — THE file to edit. Readable template: CSS + HTML
  sections + one inline JS block (particle builders, GLSL shaders, scroll
  engine, widgets). Copy lives in `{{TOKEN}}` placeholders; slot regions are
  marked `<!--SLOT:NAME-->…<!--/SLOT:NAME-->`; references three.js via a
  CDN tag and the land mask via `__LANDMASK_B64__`.
- `src/content.py` — the bilingual content model. `STRINGS`: every copy
  string is `{"en": …, "fa": …}`. `META`: one entry per key (group, fa/en
  labels, `plain|inline`, max length, anchor, page order, runtime source).
  `GROUPS`: the Persian group names in page order. `LANGS`: per-language
  head attrs and SEO URLs. Persian copy is written natively (never literal
  translation); technical terms (AI, Agent, RAG, LLM, Automation…) stay in
  English.
- `build.py` — produces BOTH flavours (below). Run `python3 build.py` after
  every source/content edit. A missing key, a leftover `{{TOKEN}}`, a
  META/STRINGS drift or a malformed slot fails the build loudly. Output is
  deterministic (no timestamps). Flags: `--site-dir DIR` (where `en/ fa/
  index.html` go, default here) and `--templates-dir DIR` (default
  `../server/templates`) — the server test suite builds into a scratch dir
  with them.
- `en/index.html`, `fa/index.html`, `index.html` — baked output, fully
  self-contained. Never edit by hand.
- `../server/templates/` — runtime output (below). Never edit by hand.
- `assets/vazirmatn-var.woff2` — Vazirmatn variable font (100–900), inlined
  into the fa baked page only (~+148 KB); referenced at
  `/assets/vazirmatn-var.woff2` (+ `<link rel="preload">`) by the fa runtime template.
- `robots.txt` — allow all; disallows `/admin`, `/api/`, `/fa/pay/`, `/en/pay/`,
  `/p/`; points at `https://sysaiq.com/sitemap.xml` (generated by Node).
- `maintenance.html` — tiny bilingual (fa first, RTL) static page in the brand
  style for nginx to serve while Node is down. No script, auto-refreshes.
- `PHILOSOPHY.md` — the design manifesto ("Sentient Luminance").

## Two build flavours

1. **Baked** (`en/index.html`, `fa/index.html`, root `index.html`): exactly
   the self-contained pages the site always had — three.js, land mask, logo,
   favicon and (fa) the font are inlined. Slot markers are stripped and the
   inner markup stays, so the markup is identical to a template without
   markers. nginx serves these as the fallback when the Node renderer is down.
   The root redirector sends visitors to the saved `localStorage['sysaiq-lang']`
   choice, otherwise to **`/fa/`** (Persian is the primary language).
2. **Runtime** (`../server/templates/home.en.html`, `home.fa.html`, ~73 KB):
   what `server/src/render/home.js` fills from the database per request.
   Plumbing tokens (`HTML_ATTRS CANONICAL ALT_FA ALT_EN OG_LOCALE SW_FA_ON
   SW_EN_ON LANG FONT_CSS FONT_PRELOAD LOGO_MARK_URI FAVICON_URI`) are
   resolved; assets are URLs under `/assets/` (three.js as
   `/assets/three.min.js?v=<sha256[:8]>`); `../fa/` `../en/` become `/fa/`
   `/en/`; the land mask is still inlined (it lives inside the hashed script).
   Every slot region collapses to `{{SLOT_NAME}}`; content keys whose META
   `source` is `token` stay as `{{KEY}}` (`plain` → `esc()`, `inline` →
   `renderInline()` mini-markup: `\n`→`<br>`, `*x*`→`<em>`, `**x**`→`<strong>`).
   The file starts with `<!-- sysaiq runtime template; do not edit -->`.
   build.py asserts that the remaining tokens are exactly
   `{keys with source "token"} ∪ {SLOT_*}`.

Also written next to the templates:
- `content-defaults.json` — every key: `{en, fa, type, group, label_fa,
  label_en, max, anchor, order, source}`; the defaults are already converted
  to mini-markup (entities unescaped, `<br>`→`\n`, `<em>`→`*…*`; no `<` left).
  The admin "متن‌های سایت" view and the renderer's `override ?? default` use it.
- `manifest.json` — `{template_sha (sha256 of src/vesper.src.html),
  generated_from, tokens, slots, assets.three, scripts, csp}`. `csp.home.{en,fa}` are
  the `sha256-…` hashes of every executing inline `<script>` in the runtime
  pages (exactly one, identical in both languages), `csp.baked.{en,fa,root}`
  the same for the baked pages (inlined three.js + the main script) and the
  root redirector. Hashes are computed on the exact bytes between `<script>`
  and `</script>`; JSON blocks and `src=` tags are excluded. The top-level
  `scripts` list repeats `csp.home.en` — that is the shape
  `server/src/lib/csp.js` reads today (`{scripts:[sha256-…]}`) to build the
  `script-src` of `/fa/` and `/en/`; keep it in step with `csp.home` (the
  build-contract test asserts both, and that `buildCsp('home')` consumes the
  committed file).

### Slots (template order)
`HEAD_META`, `JSONLD` (end of `<head>`) · `NAV_EXTRA` (inside the header
`<nav>`, after the fixed links) · `SECTIONS_AFTER_ABOUT` (after `#living`) ·
`WORK` (wraps the whole `#work` section) · `SECTIONS_AFTER_WORK` · `FAQ`
(wraps the whole `#faq` section) · `SECTIONS_AFTER_FAQ` · `CONTACT` (only the
button row under the contact h2; eyebrow + h2 stay in the template) ·
`FOOTER_LINKS`, `FOOTER_TRUST` (between `.foot-main` and `.foot-base`) ·
`SITE_DATA` (just before the three.js tag; its default content is the
`<script type="application/json" id="site-data">` block).

Marker rules: one open + one close per slot, never nested, on their own
lines (build.py drops marker-only lines whole, so the baked output has no
blank lines left behind). Keys used inside a slot region get META `source:
"slot:<NAME>"` — build.py verifies that against the template — because
they never reach the runtime template: `W1..W9_*` + `WORK_H2/WORK_HINT/
WORK_ALL` → `slot:WORK` (rows come from the `projects` table), `Q*/A*` +
`FAQ_H2` → `slot:FAQ` (`faqs` table), `CONTACT_BTN` → `slot:CONTACT`,
`AI_*` → `slot:SITE_DATA`. Custom sections rendered into the
`SECTIONS_AFTER_*` slots must be `<section class="light|solid"
data-phase="3">` — the scroll engine reads sections once at load, so they
must be in the server HTML, never injected client-side.

### #site-data and the CSP-stable main script
The AI widget strings (`AI_TITLE AI_READY AI_PH AI_HI AI_TEASER AI_ERR`)
are STRINGS keys rendered into the JSON block inside the `SITE_DATA` slot
(baked: JSON-escaped by build.py, `<` → `<`; runtime: emitted by the
renderer from the database). The main `<script>` reads them from
`#site-data` and therefore contains no `{{TOKEN}}` and is byte-identical
across languages and requests — one CSP hash. The widget builds its DOM
with `textContent`/properties, never `innerHTML` with data.

## Bilingual rules

- URL scheme: `/en/` and `/fa/`; root `/` redirects (fa by default) and is `noindex`.
  Each page carries canonical + `hreflang` fa/en/x-default alternates.
- The header language switcher (`.lang-sw`, FA | EN) preserves
  `location.hash` and persists the choice to `localStorage['sysaiq-lang']`.
- RTL: the fa build sets `<html lang="fa" dir="rtl">`. `[dir="rtl"]` CSS
  overrides fix physical text-aligns, swap the two HUD corners, and zero
  `letter-spacing` (it breaks Persian letter joining). Technical LTR runs
  (eyebrows, HUD, stat keys, footer tags) carry `dir="ltr"` inline.
- Adding copy: add a `{{TOKEN}}` in the template AND a key in `STRINGS`
  AND an entry in `META` (same position = page order) — the build asserts
  all three directions, so the languages and the admin can never drift.
  `type: "inline"` only when the default carries `<br>`/`<em>`/entities and
  renders as element text; anything that lands in an attribute stays `plain`.

## Architecture (all inside src/vesper.src.html)

1. **Shape builders (CPU, run once at load)** fill Float32Array morph
   targets, one entry per particle: `orbPos` (unit dirs on quantized
   latitude rings), `galaxyPos` (broken concentric rings + halo + core),
   `earthPos` (vec4: xyz + land flag, rejection-sampled against the land
   mask; oceans kept sparse), `aiPos` (vec4: xyz + letter flag, sampled
   from an offscreen 1280×320 canvas rendering "SysAIQ", auto-fit to
   canvas width).
2. **Vertex shader** mixes targets by phase weights `uW` (x=orb, y=galaxy,
   z=unused) and `uW2` (x=earth, y=letters), adds per-phase motion (orb
   wave, galaxy differential rotation + tilt, ocean shimmer, letter
   hover), cursor repulsion (damped for earth/letters), click ripple, and
   per-phase color/alpha.
3. **Scroll engine** — sections carry `data-phase` (0 orb, 1 galaxy,
   2 earth, 3 letters). `currentPhase()` picks the section under the
   viewport centre; weights ease toward the target each frame. Per-phase
   camera distance `PHASE_CAMZ` (letters use 7.0 to fit the wide word),
   vertical offset `PHASE_YOFF`, HUD label `PHASE_LABEL`.
4. **Page chrome** — fixed header pill nav + language switcher + mobile
   hamburger (≤900px: `#nav-toggle` toggles `nav.open`, a full-width glass
   dropdown under the pill; `aria-expanded`/`aria-controls`, closes on link
   click and Escape; hidden on desktop so the desktop pill is unchanged),
   boot loader, corner HUD (auto-fades over opaque UI; corners swap under
   RTL), reveal-on-scroll (`.rv` + IntersectionObserver), FAQ accordion,
   scroll-% readout, AI assistant widget (strings from `#site-data`).

## Conventions

- Keep the four PHASE_* arrays and section `data-phase` values in sync
  when adding/removing a phase; weights are normalized each frame.
- Section design language: dark sections (`.dark-sec`) are transparent over
  the canvas — reserved for the WebGL acts; `.light` (paper) and `.solid`
  (opaque `#070a12`, light text) are opaque. Both are in the HUD `occluders`
  list, so the HUD fades over them. Mono eyebrows `[ SYSAIQ—NAME / SYS.0N ]`,
  thin 300-weight display headings.
- Don't call Date.now()/Math.random() for anything that affects geometry —
  keep it seeded and reproducible.
- No inline event handlers and no new inline `<script>` blocks (the home
  page CSP is hash-based; JSON data blocks are fine).
- Contact email is `hello@sysaiq.com` (in the template, not content.py).

## Work showcase

`#work` (light, inside the `WORK` slot) holds the cinematic stage
(`#sc-stage` cross-fading `.sc-slide` images + `#sc-bar` progress) and the
`#sc-list` index of `.sc-row` rows; copy comes from `W1..W9_{T,D,G}` tokens
in the baked page and from the `projects` table at runtime. Hover/focus a
row to preview; auto-cycles while visible; 3D tilt on hover. A runtime
renderer must keep these ids/classes for the script to pick the slot up.

## Verify

`cd server && npm run dev` (port 3100, `SITE_DIR=../vesper-project`) and
open `http://127.0.0.1:3100/fa/` and `/en/` at several scroll positions
after changes; phases settle in ~8–10 s (weights ease in). Check: no
console errors, letterforms spell "SysAIQ", fa page is RTL with joined (not
spaced-out) Persian glyphs, switcher keeps position, the AI widget opens
with the fa/en strings, the hamburger toggles the nav at 375 px.
`cd server && npm test` runs `test/template/build-contract.test.js`, which
rebuilds into a scratch dir and asserts the token/slot/hash contract and
that the committed output is up to date.
